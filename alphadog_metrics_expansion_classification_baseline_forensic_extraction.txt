- Bug: "found 10 real residual violations (singles>hits) even after reconcileSubsetOfConstraints
  ran on baseline completion" - root cause: a single pass isn't sufficient because a superset
  prop (hits) can itself get clamped by ITS OWN constraint (hits->hits_runs_rbis) during the
  same pass, but a subset (singles->hits) checked earlier in iteration order won't see that
  newly-updated value - a genuine cascading-order bug, quoted/paraphrased from the session's

- Fix (exact real code, quoted): loops the full constraint set repeatedly "until no more

  if (passClamped === 0) break; }). Each pass's SQL:
  ```
  UPDATE baseline_v6_current
  SET hit_probability_0_100 = (SELECT s.hit_probability_0_100 FROM baseline_v6_current s
      WHERE s.player_id = baseline_v6_current.player_id AND s.canonical_prop_key = ?
      AND s.line_value = ? AND s.selected_side = ?),   -- superset's value
      formula_version = formula_version || '+subset_clamped'
  WHERE canonical_prop_key = ? AND line_value = ? AND selected_side = ?    -- subset's key
    AND hit_probability_0_100 > (SELECT s.hit_probability_0_100 FROM baseline_v6_current s
      WHERE s.player_id = baseline_v6_current.player_id AND s.canonical_prop_key = ?
      AND s.line_value = ? AND s.selected_side = ?)
  ```
