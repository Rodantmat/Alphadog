**Operating model locked by the person, this session (see /areas/alphadog-nba.md in assistant memory for the full statement)** — recorded here as the canonical, binding spec for all future NBA sessions:
- NBA season is currently off (~1 month until start) — no live data yet. Current priority: backfill static + historical data, and design the system end-to-end, not live operation.
- **No runner/orchestrator automation** — same manual, Coworker-scheduled, worker-by-worker operating model MLB currently uses. Explicitly rejected building an NBA orchestrator.
- **3 runs**: (1) *Static differential* — rarely-changing data (calendar, teams, players, rosters, arenas, possibly referees). (2) *Delta daily* — game logs / day-changing data, with a backfilled base + daily incremental mining, and this run also builds **the baseline** (via a multi-layer logic classifier: player × prop-line × variation × direction, each with its own thresholds/caps/bonuses/penalties) — described as "the heart of the system." (3) *Master run*, 4 stages: Board (PrizePicks/Sleeper/Underdog) → Daily Context (individually-mined factors, each with a fallback so it's never empty — referee, arena, fatigue, injury, and more, all still to be locked, turned into multipliers/coefficients/bonuses/penalties) → Market/Odds (book data, game- and player-prop-level) → Scoring Engine (combines baseline + enrichment into final numbers).
- **Chat/worker granularity**: one new chat per big data domain, one worker per small piece of work, to avoid overloading any single session. Every new NBA chat should first study the equivalent live MLB worker, research whether real improvements exist, then build fresh with NBA sources — not a blind port.
- **Hard constraints, every NBA chat**: never edit anything in the MLB system; every NBA worker file lives in a dedicated NBA repo subfolder, clearly labeled, no mixing with MLB; every tunable numeric variable (bonuses, penalties, caps, timeouts, retries, chunk sizes, etc.) lives in the database, never hardcoded, so it's SQL-changeable without a deploy; NBA gets a fully separate data universe — its own new tables, independent from MLB's; every chat must log important steps/issues/fixes to this log system.
- **Research standard**: deep online research is mandatory; Gemini consultation on complicated decisions is mandatory (Gemini is a useful, not authoritative, reference — its conclusions get independently re-derived, per the lessons doc).
- **UI**: the existing "certification center" (leg aggregator / slip builder) will be reused as-is for NBA once ready — no separate NBA UI planned.
